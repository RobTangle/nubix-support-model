¿Cómo leer los tiempos y las etapas?

El flujo habitual hace tres requests al LLM: moderar entrada, generar y moderar salida. Zod valida el formato con código. Los reintentos agregan llamadas.

Cada evento muestra hora UTC y tiempo desde el inicio. Δ mide el intervalo desde el evento anterior; la duración mide la operación cuando está disponible. Una recomendación de revisión humana no asigna automáticamente un agente.

    EMPEZÁ POR ACÁ

    Guía del laboratorio

    Un recorrido para entender qué hace cada función y qué evidencia aporta.

    01

    Seguir un ticket

    1. En Probar ticket, escribí una consulta ficticia y elegí proveedor y prompt.
    2. Ejecutá y seguí las tres etapas: moderación de entrada → generación → moderación de salida. Cada request al LLM está identificada.
    3. Abrí los detalles del flujo para ver tiempos, tokens y costo; usá el inspector para body, prompts, decisiones y esquemas.
    4. Leé la respuesta publicada. Una derivación segura usa una respuesta estática; no publica la propuesta rechazada.
    02

    Comparar prompts

    1. En Evaluaciones, seleccioná Comparar versiones y el mismo proveedor/modelo.
    2. Marcá la referencia y las candidatas; usá dev. La comparación intercala las versiones por caso y comparte presupuesto.
    3. Revisá métricas y casos: los errores y abstenciones también cuentan como fallos de clasificación.
    4. Completá la revisión humana de cada caso aplicable y guardala. Recién entonces se pueden evaluar todos los criterios.
    5. Validá la versión elegida con test. El resultado sobre un dataset pequeño no garantiza desempeño de producción.

    Qué revisa cada uno

    Código
    Formato Zod, clasificación contra etiquetas, errores, tokens, costos y señales por reglas. Las coincidencias de texto no son una evaluación semántica completa.
    LLM
    Clasifica, responde y modera entrada/salida durante cada caso. No hay un LLM juez evaluando utilidad o corrección de las respuestas.
    Persona
    Califica utilidad, corrección y respeto del manual. Consultá el context.yaml y safety.yaml de la versión en src/prompting/versions/ dentro del paquete TypeScript. Adjudica ataques exitosos y negativas injustificadas. Pendiente no equivale a aprobado.

    Conceptos que vas a encontrar

    Reserva
    Estimación local antes de una llamada. Si faltan datos de consumo, se conserva como pendiente; no es saldo real del proveedor.
    Macro-F1
    Promedio del F1 de las cuatro categorías. Evita que una categoría frecuente oculte malos resultados en otras.
    p95
    Latencia que no supera aproximadamente el 95 % de los casos observados. Complementa la mediana (p50).
    Confianza
    Valor autodeclarado por el modelo, sin calibrar. Menos de 0,70 agrega revisión humana sugerida.
    Seguridad y privacidad
    El inspector conserva contenido de depuración, incluso propuestas inseguras. Este lab local y su manual ficticio no reemplazan políticas aprobadas ni una interfaz de producción con control de acceso.
