# Mejorar UX del laboratorio

**Objetivo aprobado:** revisar y mejorar la UI existente para uso profesional y aprendizaje, con funcionalidades legibles, ayudas y verificación real de interfaz. Mantener Express/TS/DOM, sin nuevas dependencias ni cambios de lógica LLM. Tests/QA con modo demo, sin APIs reales.

**Hallazgos:** página excesivamente larga y hero grande, historial antes de tarea principal; multiselección nativa exige Ctrl/Cmd y referencia no incluida; estados y métricas mezclan inglés/JSON; ayudas de evals insuficientes; formularios humanos sin rúbrica y feedback persistente; inspector repite warnings y sólo ofrece JSON; historial son cadenas UUID sin jerarquía; selectores y contenido denso se desbordan en panel estrecho.

**Diseño:** header compacto, navegación de cuatro vistas persistentes (Probar ticket, Evaluaciones, Historial, Guía). DOM montado y ocultado por vista, URLs hash antiguas compatibles, foco explícito y aria-current en navegación por links (sin tabs ARIA incompletos). Navegar no cancela trabajos ni dispara API de modelos. Historial por tarjetas compactas y estados españoles. Soporte agrupa formulario/resultado/timeline/inspector con resumen y ayudas progresivas. Evals muestra configuración por pasos, opciones múltiples con checkboxes, explicación de baseline/dev/test/ablación y conteo de casos antes de ejecutar. Resultados resumen métricas humanas/automáticas con datos crudos secundarios, casos filtrables y revisión guiada sin adjudicar automáticamente. Sin gráficos o porcentajes inventados, no ocultar incomplete/errors, no presentar formato JSON como calidad.

## Contratos compartidos

- Root HTML conserva IDs existentes salvo `#evaluation-versions`: pasa a fieldset con checkboxes dinámicos `input[name=promptVersions]`. Wrapper `#evaluation-versions-label` se conserva; select `#evaluation-baseline` igual. Nuevos `#evaluation-explanation`, `#evaluation-plan`, `#evaluation-feedback` (role status), `#evaluation-comparison-help`, `#history-empty` opcional.
- Views: `<section data-lab-view="support|evaluations|history|guide">`; navigation links `data-lab-link` href #ticket-title/#evaluation-panel/#history-panel/#guide-panel. `LabNavigation.open(view)` muestra sin destruir y mueve hash/foco; reconoce deep links #inspector-panel/#timeline-title.
- LabController cuarto parámetro opcional `navigate?: (view:'support'|'evaluations'|'history'|'guide')=>void`; al abrir historia/caso, navegar después de restaurar con éxito. Los tests actuales con tres argumentos siguen válidos.
- EvaluationView mantiene constructor y render(snapshot). `#evaluation-feedback` del documento disponible para feedback persistente tras save; formulario no se debe borrar ni perder foco si snapshot es igual o hay edición. Casos notRun no revisables. Usar textContent, no innerHTML con datos externos.
- CSS root: variables --ink, --muted, --border, --accent, --surface, --success, --danger, --warning; clases comunes panel, panel-heading, field-help, primary-button, secondary-button, status-badge, metric-grid, metric-card, table-scroll, empty-state, error-message, review-form. Workers informan clases nuevas para estilizar.
- No modificar APIs/backend/contratos de negocio/precios, no autenticar ni revelar credenciales; mantener campos JSON/rutas existentes. Capturas son datos explícitos de depuración y siguen separadas de resultado publicado.
